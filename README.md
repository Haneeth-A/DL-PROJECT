# DL Project — information vs architecture for Indian electricity-demand forecasting

Course project, IIIT Raichur (Deep Learning). We ask a narrower question than "which model wins":
**what limits day-ahead and week-ahead forecast accuracy for Indian state demand — the architecture, or
the information we feed it?** and whether that answer survives structural breaks.

Three model families (LSTM, PatchTST, iTransformer) are compared at three information sets, plus two
simple baselines and a linear baseline. The required modification is a leak-safe regime-aware input
normalisation (M2), ablated honestly, including against the null result.

- **Data:** [RE-FUSED](https://doi.org/10.5281/zenodo.23301897) v1.0 — 34 entities, daily, 2020-01-01 …
  2025-12-31, target `dem_energy_met_gwh` (GWh/day). CC BY 4.0. See `Data/README.md`.
- **Horizons:** h = 1 and h = 7 days. Lookback 90 days.
- **Windows:** train 2020-01 → 2023-06 · val 2023-H2 · test 2025 (primary) and 2024 (secondary) ·
  rolling-origin over 2024–2025.
- **Reports:** `reports/`, `paper/`.

## Layout

```
Data/processed/     panel.parquet + metadata (A's build); no raw data in git
EDA/                audit, regime, weather and baseline scripts (A)
Role-a/             data/EDA evidence guide (A)
src/                pipeline: data, models, train, evaluate, stats
reports/            figures, results CSV, predictions, report PDF, slides
paper/              manuscript + bibliography
docs/               data dictionary, methodology, limitations
```

## Setup

Windows (the environment this repo was built in) and Linux:

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux:   source .venv/bin/activate
pip install -r requirements.txt
```

`Data/Raw/` is gitignored. Re-download with `python -m src.download_data` and verify
`Data/processed/source_sha256.txt`; the expected hash is recorded in `Data/README.md`.

## Reproduce

```bash
make data      # download/verify raw -> build model panel, splits, regimes, neighbours
make train     # all cells and seeds -> runs.csv + predictions
make eval      # metrics + statistical tests
make figures   # all figures and tables
make all
```

Every reported number is generated by a script from a CSV in `reports/results/`; no number is typed by
hand. Seeds 42/43/44. Hardware: one 8 GB laptop GPU, so runs are sequential and small.
